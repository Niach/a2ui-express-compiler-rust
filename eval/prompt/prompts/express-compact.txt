# A2UI Express DSL Output Contract

You must output the user interface using A2UI Express.

IMPORTANT: You MUST always surround the entire A2UI Express block with the literal sentinel tags `<a2ui>` and `</a2ui>` (always include both the opening and closing tags; do NOT wrap the tags in backticks or replace the opening tag with a markdown code fence such as ```a2ui).

The host compiler will compile your A2UI Express output into the correct JSON envelopes automatically.

## Grammar Rules

1. Component constructors can be assigned to variables or nested inline inside parent component arguments:
   header = ComponentA(prop1="val1")
   root = ComponentB([header, ComponentC("Click", action=Event("submit"))])

   Keyword arguments (`param=value`) and positional arguments with `_` placeholders are supported.

   Variable names MUST start with a letter or underscore, and only contain letters, digits, and underscores.

2. The interface tree must have a single entry point assigned to the reserved variable 'root'.

3. Primitives:
   - Strings: Quoted with `"` or `"""`. Support for `\n`, `\t`, `\\`, and `\"` escapes.
     Raw Strings: Prefaced by `r` (e.g., `r"..."` or `r"""..."""`), with no escape processing.
   - Numbers: write as integers or decimals, e.g., 42
   - Booleans: write true or false
   - Null values: write null
   - Dates & Times: Values for date-time inputs (e.g. in DateTimeInput) must strictly use RFC 3339 format with a timezone offset (e.g. "2026-03-14T00:00:00Z").

4. Lists: represent as arrays, e.g., [child1, child2].

5. Maps: represent as key-value blocks, e.g., {title: "Overview", child: contentCol}. Map keys are always literal strings (dynamic variable resolution is not supported for keys).

6. Data bindings: prefix absolute paths in the data model with '$', e.g., $/user/firstName.
   Prefix relative list scopes with '$', e.g., $firstName.
   A lone '$' represents an empty relative path which resolves to the root of the current context (e.g. inside a template, representing the entire item itself).

7. Logic and validation: prefix client check rules with '?', e.g., ?required or ?regex("^[0-9]{5}$"). To specify a custom error message for validation failures, append it as an extra string argument, e.g. ?regex("^[0-9]{5}$", "Postal code must be 5 digits").

8. Action events: represent server-side actions using the Event helper, `Event(name, context?, userMessage=...)`:
   Event("save_deal", {rep: $/form/rep})
   Event("reply", userMessage="Replying now")
   Event("save_deal", {rep: $/form/rep}, userMessage=$/form/summary)
   The context map is optional. Pass `userMessage=` as a keyword argument (a string, `$path` binding, or function call) to set the message shown on the user's behalf when the event fires.

9. Nested functions: call client functions directly using catalog signatures, for example myFunction("value").

10. Data model population: Assign a value directly to an absolute data path (e.g. $/path/to/key = "value") to populate or initialize values inside the shared dataModel. The value can be a primitive, array, or map.

11. Dynamic list templates: If a component expects a template child list, represent it using the _template helper:
    _template($/path/to/list, itemTemplate)
    And define the template component variable on another line, utilizing relative path references prefixed with $:
    itemTemplate = Image($url)

12. To delete a user interface surface, output the standalone `deleteSurface(surfaceId)` command (no variable assignment):
    deleteSurface("dashboard-surface-1")

13. To have the renderer run a function right away, output the call as a standalone command (no variable assignment):
    required(...)
    Only these functions can be called this way: `required`, `regex`, `length`, `numeric`, `email`, `formatString`, `formatNumber`, `formatCurrency`, `formatDate`, `pluralize`, `and`, `or`, `not`, `percent`, `add`, `sub`, `eq`, `lt`, `clamp`, `cond`, `fallback`, `concat`, `coalesce`, `text`, `map`, `len`, `fill`, `formatPercent`, `formatRelativeTime`, `filter`, `mul`, `div`, `mod`, `round`, `floor`, `ceil`, `abs`, `min`, `max`, `today`, `now`, `dateTime`, `dateAdd`, `dateDiff`, `startOf`, `endOf`, `weekday`, `isoWeek`, `hours`, `formatDuration`, `orElse`, `expr`.

14. Static properties: Arguments annotated with '(static)' in the signatures below MUST be defined as literal values or arrays inline. You CANNOT use a dynamic data binding path (prefixed by $) for these arguments.

15. Required actions: Parameters named 'action' (or annotated in component signatures) are strictly required. You must pass a valid Event (e.g. Event("click")) or function call. If no specific action is described in the user request, you must provide a dummy click event like Event("click") instead of passing null or omitting the parameter.

16. Surface targeting: Output `surface(surfaceId)` to specify or target a user interface surface:
    surface("dashboard-surface-1")
    root = Label(...)

## Component Signatures

Instantiate components with these signatures, naming every argument (`Button(label="Save", variant="outline")`, `Stack(children=[a, b])`). Do not name any other key.
Notation: `name?` is optional; `name~` also takes a data binding ($/path) or a function call, any other property takes a literal only (this replaces the `(static)` annotation); `:n` marks a number (write 1.5, not "1.5"), `:b` a boolean. Under a signature, `- prop: type` gives a property's values: `a|b|c` is one of these strings (write "a"), `{key, key: type}` is a map with those keys (`{a|b: type}`: keys a and b, both of that type), `[type]` a list, `Action` an Event(...) or function call, and a capitalized name a type from Shared Types.
Actions go in a component's `on` map, keyed by event: on={change: Event("save")}. No component takes an `action` argument.

## Catalog Instructions

Exponential UI core: shadcn-named components for app-shaped surfaces.

## Catalog rules

1. Components are flat: `{id, component, ...props}`. Exactly one has the id `root`. Ids are identifiers (letters, digits, `_`). `children` are ids (`["a", "b"]`), never inline components, or `{componentId, path, key?}`: one `componentId` per item of the array at `path` (`key` = the item field naming it). `slots` = `{name: id}`.
2. A dynamic prop takes a literal, a binding `{"@path": "/json/pointer"}` or a call `{"@call": "name", "args": {…}}`. Keep data in the data model and bind to it; a path without a leading `/` reads the current item.
3. `on: {<event>: action}`: an action is `{event: {name, context?, userMessage?}}` (sent to the agent) and/or `{functionCall: {"@call", args}}` (runs on the renderer: a catalog function, `set`, or a host function such as `app_toast`).
4. `visible: false` (or a binding) removes a component and its space. Inputs take `checks: [{condition, message?}]`; a condition is a binding or a call (`required`, `regex`, `length`, `numeric`, `email`).
5. Lay out with Page, Stack, Grid, Card, SplitView, Sidebar and List. A row of controls is a Toolbar, fields side by side a FieldGroup, the Cancel/submit row FormActions; Box + `style` only for the rest. Wrap fields in Form.
6. Prefer catalog components over Markdown, labels and tones over colours. A colour is a `$color.*` token, never `#hex`. Leave built-in copy (Cancel, Search…) unset: it is localized.
7. One default Button per screen (the submit or main action); the rest outline, secondary or ghost.
